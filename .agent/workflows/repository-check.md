# Repository Check Workflow

## Authority

This workflow verifies that repository practices for a feature comply with INT
SDD Architecture and Repository Standards.

Governing rule: `.agent/rules/int-sdd-architecture.md` §12–20
Non-negotiables: `.agent/rules/int-sdd-non-negotiables.md`
Lifecycle: `.ai-context/lifecycle.md`

Run this workflow:

- Before creating a feature branch (to verify the naming and scope intent).
- Before creating a PR (to verify scope, traceability, and compliance).
- As part of Gate 2 review preparation.

---

## Inputs Required

- Feature slug: `<feature-slug>`
- Branch name (proposed or actual): `<branch-name>`
- Spec: `.ai-context/specs/<feature-slug>.spec.md`
- Plan: `.ai-context/plans/<feature-slug>.plan.md`
- Tasks: `.ai-context/tasks/<feature-slug>.tasks.md`
- PR title and description (if PR exists)

---

## Part 1 — Feature Slug Verification

- [ ] **[BLOCKING]** A valid feature slug exists (kebab-case, human-readable,
      specific, 3–5 words).
- [ ] **[BLOCKING]** The feature slug is consistent across:
      - Spec file name: `.ai-context/specs/<feature-slug>.spec.md`
      - Plan file name: `.ai-context/plans/<feature-slug>.plan.md`
      - Tasks file name: `.ai-context/tasks/<feature-slug>.tasks.md`
      - Test cases: `.ai-context/test_cases/<feature-slug>.test_cases.md` (when applicable)
      - Branch name: `feature/<feature-slug>`
- [ ] The slug is unique — no other spec uses the same slug.

---

## Part 2 — Branch Verification

- [ ] **[BLOCKING]** Branch name follows the repository convention:
      - Feature branch: `feature/<feature-slug>`
      - Fix branch: `fix/<issue-slug>`
      - Hotfix branch: `hotfix/<incident-slug>`
- [ ] **[BLOCKING]** Branch name traces directly back to the feature slug or
      issue/incident identifier.
- [ ] **[BLOCKING]** Branch is NOT named with a prohibited vague name:
      `dev`, `test`, `new-feature`, `changes`, `final`, `final-v2`, `wip`,
      or any name that cannot be traced to a SDD artefact.

---

## Part 3 — Branch Scope Verification

- [ ] **[BLOCKING]** Branch scope matches the corresponding spec — it does not
      contain work belonging to a different feature spec.
- [ ] Branch does not silently include unrelated refactors.
- [ ] Branch does not silently include unrelated bug fixes.
- [ ] Branch does not silently include architecture experiments.
- [ ] Branch does not silently include cleanup work not approved in the spec.
- [ ] The changes in the branch can be reviewed against the spec's acceptance
      criteria in a single sitting.

If reviewing all changes against the spec requires more than one sitting:
report this as a scope concern and flag for possible spec decomposition.

---

## Part 4 — PR Traceability Verification

- [ ] **[BLOCKING]** PR title contains the feature slug or is otherwise directly
      traceable to the feature spec.
- [ ] PR description references:
      - Feature spec (`.ai-context/specs/<feature-slug>.spec.md`)
      - Task IDs implemented (`<feature-slug>.T01`, `.T02` …)
      - AC verification evidence (`<feature-slug>.AC1` satisfied by …)
- [ ] PR scope is bounded by the feature spec — no out-of-scope work is mixed in.

---

## Part 5 — Task ID Traceability in Commits

- [ ] Commits in the branch reference task IDs (e.g., `Implements <feature-slug>.T03`).
- [ ] **[BLOCKING]** Commits do NOT contain AI-attribution text:
      `Generated by Claude`, `Generated by Codex`, `AI-assisted`,
      `Written by AI`, `Co-authored by AI`.
- [ ] Commit messages are human-readable and traceable to SDD artefacts.

---

## Part 6 — Merge Strategy

- [ ] The planned merge is a squash-merge to main (or equivalent protected branch).
- [ ] Individual incremental AI-generated commits will be consolidated into one
      logical squash-merge unit.
- [ ] The squash-merge commit message references the feature slug and is traceable
      to the SDD artefact chain.

---

## Part 7 — Internal SDD Artefact Control

- [ ] `.agent/` directory is present and intact in the internal repository.
- [ ] `.ai-context/` directory is present and intact in the internal repository.
- [ ] No SDD governance artefacts have been moved to arbitrary locations.
- [ ] Client-facing repository exposure of `.agent/` and `.ai-context/` is
      explicitly governed (excluded by default unless SOW permits).
- [ ] No secrets, PII, or confidential internal engineering context is exposed
      in any repository (internal or client-facing).

---

## Part 8 — Human Accountability Confirmation

- [ ] The feature has a named human engineer accountable for the merged changes.
- [ ] Gate 2 human review is recorded or pending — it is not skipped.
- [ ] AI generation of code or tests does not substitute for human Gate 2 review.
- [ ] Merge is pending human Gate 2 completion.

## Critical Reminders

1. **One feature slug = one spec = one branch = one PR = one squash-merge.**
2. **AI attribution in commits is prohibited under INT SDD.**
3. **Task-ID traceability in commits is allowed and encouraged.**
4. **Branch scope must be reviewable against the spec — split the spec if not.**
5. **`.agent/` and `.ai-context/` must remain in the internal repository.**
6. **Client-facing exposure of internal artefacts requires explicit SOW authorization.**
7. **Gate 2 human review is required before merge — this check does not replace it.**
